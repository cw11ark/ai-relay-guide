## 2. 同一个任务怎样算账

> **两种计费没有普适的谁更省**——取决于每次请求的 token 量、上限和成功率。别信任何"最低价"结论（包括本文的），代入自己的负载算：

```
假设（仅为算术演示）：输入 ¥1/M、输出 ¥2/M，每次 1 万输入 + 2 千输出：
按量成本 = (10000/10⁶)×¥1 + (2000/10⁶)×¥2 = ¥0.014 / 次

若某按次站报价 ¥0.0002/次（同模型、不超限）→ 此负载下按次约为按量的 1/70。
分界思路：等效单次成本 = 输入token×输入单价 + 输出token×输出单价；算出来再和按次报价比。
```

- **按次**计费要标明上下文/输出上限（如 42K）与失败是否计费——超限任务按次再便宜也用不了。
- **倍率**计价（如 0.075）缺计费基准 ⇒ 不能换算成实付人民币，本文不做该换算。
- **预扣冻结 ≠ 最终费用**：超长上下文单发按上限预扣（AgentRouter 观察约 $36 账面额度），释放规则因时而异。
- 有实际账单后可算"完成任务成本"（总实付 ÷ 验收完成任务数）——但那是窗口观察量，不是质量证明。

## 3. 接入前先看限制与风险（第一个外链之前）

1. **数据隐私**：中转站能看到全部请求内容。各家保存/日志政策未经核验 ⇒ 无论条款写了什么，密钥、客户数据、保密代码不过中转渠道，先脱敏。
2. **模型身份未证实**：本文校验只做到"响应 model 字段与请求一致/不一致"的观察；中转方技术上可改写字段。正文型号一律按"渠道标称型号"理解。
3. **隐藏提示词注入**：AgentRouter 部分链路观察到附加指令，改变应用指令边界——编程 Agent / JSON 输出等提示词敏感场景先小流量验证。
4. **失败与计费**：429 = 限流（退避 + 上限，连发放大拥堵）；500/超时重试前确认是否已扣费、任务是否幂等。
5. **接口协议差异**：Careke 仅 OpenAI 协议（Anthropic 直打 500）；接入前核对协议兼容。

## 6. 我们怎样观察，哪些尚未验证

- **单次实测**（TTFB 3.7s/7.1s/2.5s 等）：日常单发观察值，无多轮采样，不构成推荐依据；TTFB ≠ 完整响应时长
- **连续日志**：AgentRouter ~30 天（channel-watch 故障日志）；Careke Grok 线 ~7 天；其余为间断观察——**各站窗口不同，不混称"30 天横评"**
- **字段校验**：响应 model 字段比对 + 少量指纹抽查；**埋针命中 ≠ 全文完整性；状态码 ≠ 有效输出**
- **报价**：官网公告口径快照 2026-10-18；倍率基准、起充额、cache 价格、统一负载实付——**均未核验**
- **商家自述**（"满智商""绝不降智"等）：一律不采信为本仓结论
